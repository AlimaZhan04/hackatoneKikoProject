# KIKO Architecture Lab — интерактивная защита

Сервис от 24.11.2026: http://localhost:3003. Магазин сохраняет свой дизайн и работает на http://localhost:3001. Оба используют одну PostgreSQL `kiko` и одинаковые серверные модули CRUD; сервис защиты запускается отдельным процессом `server/lab-service.mjs`.

## Как запустить

В PowerShell:

```powershell
cd "C:\Users\HP\Desktop\kiko_project"
npm run db:local
npm run db:seed
npm start
```

Откройте http://localhost:3003. Схема, опыты и чтение доступны гостю. Для записи войдите через кнопку «Войти», используя ту же учётную запись администратора, что в магазине. Локальные параметры находятся в `.env`.

`npm run start:lab` собирает и запускает только сервис защиты. `npm run lab` запускает его с уже готовой сборкой. Порт можно изменить переменной LAB_PORT. Чтобы остановить процессы, нажмите Ctrl+C в терминале запуска.

## Что показать преподавателю

1. **Схема модулей.** Выберите validateProduct: справа видны функциональная связность, СС 10, задачи и путь к файлу. «Посмотреть код» открывает настоящий исходник с диска.
2. **Стрелки.** Выберите связь «ID · СЦ 1»: объяснение сцепления по данным и контракт deleteProduct(id). Связь «Товар · СЦ 3» показывает структуру, передаваемую при создании и изменении. Управляющие вызовы выделены отдельно.
3. **Опыты → Функциональная.** Проверьте цену −1, затем 100. Вызывается общий validateProduct, записи в БД нет.
4. **Опыты → Коммуникативная.** Введите поиск. Таблица и четыре счётчика работают с одной коллекцией, но поиск меняет только показанные строки; статистика относится ко всей коллекции.
5. **Каталог и CRUD.** Войдите администратором, добавьте собственный тестовый товар. Измените цену. Он доступен и в магазине, и в PostgreSQL. Не меняйте чужие товары для демонстрации.
6. **Загрузка фотографии.** Выберите созданный товар, загрузите JPEG/PNG/WebP. Этапы: проверка содержимого → WebP → транзакция → поле image. Информационная связность, СС 9.
7. **Опыты → Процедурная.** Запустите успешный сценарий и отказ записи. При отказе форма не закрывается. Это настоящий submitProduct с учебными persist/refresh без записи в БД, СС 5.
8. **Удаление.** Удалите только свой тестовый товар. В «Пути последнего запроса» видны реальные отмеченные этапы DELETE. Нажмите «Показать на схеме» — модули подсветятся по порядку.
9. **Антипаттерн.** Переключите модель: вымышленные общие данные, управляющие флаги и смешение обязанностей. Это объяснение плохой организации, а не действующий код магазина. Опыт с плохим порядком также не изменяет БД.

## Откуда берётся визуализация

- `shared/lab-model.mjs` — вручную составленная карта вызовов, контрактов и учебных объяснений.
- `src/lab/LabApp.jsx` — схема, карточка выбранного модуля/стрелки, опыты, каталог и просмотр кода.
- `src/lab/client.mjs` — клиент настоящего API; передаёт управляющий параметр method.
- `server/lab/trace.mjs` — контекст одного запроса через AsyncLocalStorage. Только для заголовка X-Kiko-Lab: 1 сервер добавляет X-Kiko-Lab-Trace с названиями выполненных этапов.
- `server/lab/routes.mjs` — статус БД и чтение исходников только из фиксированного списка модулей. Произвольный путь и `.env` через этот API недоступны.

Журнал не является автоматической трассировкой всех вызовов JavaScript. В нём показаны реальные ручные отметки: маршрут, валидация, обработка фото, репозиторий, запрос драйверу и успешное выполнение SQL/COMMIT. Значения товара, пароли, cookie и строка подключения в журнал не включаются. Обновление списка после сохранения не заменяет журнал операции записи.

Баллы СС 10/9/7/5 и СЦ 1/3 взяты из задания. СС больше — лучше; СЦ меньше — лучше. Числовой балл управления не придуман. «Информационная» сохранена по лекции; конвейер также называют последовательной связностью. Для сцепления по образцу использована широкая трактовка передачи структуры; строгий подход дополнительно рассматривает избыточные поля. Схема не выдаётся за автоматический анализатор качества.

## Проверка

- `npm test`: 10 проверок, включая существование файлов и целостность карты.
- `npm run test:api`: PostgreSQL, авторизация, CRUD, фото, newsletter; дополнительно статус лабораторной, разрешённый исходник, запрет неизвестного исходника, порядок этапов успешного POST и отсутствие SQL при отклонённой цене.
- `npm run build`: обе страницы собираются отдельно; CSS сервиса не подключается к магазину.
- Chromium/Playwright: опыты с отрицательной и положительной ценой, успех/отказ submitProduct, фильтрация общего массива, настоящий CRUD и фото, совместимость с API магазина, воспроизведение пути, выбор узлов и стрелок, фильтры, масштаб, клавиатура и диалог исходника.
- Пройдены 27 функциональных проверок в трёх браузерных сценариях и 12 проверок разделов на ширинах 1440, 768 и 390 пикселей. Горизонтального переполнения документа и необработанных ошибок JavaScript в этих сценариях нет. Большая схема и таблица на телефоне прокручиваются внутри своих областей.
- Найденное при проверке перекрытие области нажатия двух стрелок исправлено: метки связей вынесены поверх линий, выбор каждой метки не перехватывается соседней стрелкой.

## Локальная база на этом компьютере

При запуске 24.11.2026 прежняя папка отдельного кластера `%LOCALAPPDATA%\KikoProjectPostgres\data` отсутствовала. Отдельный кластер 127.0.0.1:5433 создан заново с сохранёнными настройками `.env`, 15 учебных товаров импортированы из `db.json`. Это восстановление исходного учебного каталога; прежние дополнительные записи отсутствовавшего кластера из `db.json` восстановить нельзя. Установленная PostgreSQL на 5432 не изменялась. Скрипт теперь умеет инициализировать отсутствующий кластер с существующей конфигурацией только для ожидаемых локальных параметров KIKO.
